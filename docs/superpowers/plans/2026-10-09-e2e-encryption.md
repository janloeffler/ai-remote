# E2E encryption — implementation plan

Spec: `docs/superpowers/specs/2026-10-09-e2e-encryption-design.md` (source of truth for
formats, AADs, endpoints, behavior). Branch: `feat/e2e-encryption`.

## Goal

Optional (`E2E_ENCRYPTION`) end-to-end encryption between Mac agent and browser; plaintext
mode stays byte-for-byte identical in behavior.

## Order and dependencies

```
T1 shared render_core + agent deps
 ├─ T2 agent crypto + vectors + setup CLI      (agent/)
 └─ T3 backend E2E mode                        (backend/app python + templates)
       ├─ T4 agent integration                 (agent/)          needs T2, T3 contract
       └─ T5 browser crypto + UI               (backend/app/static, templates, i18n) needs T2 vectors, T3 templates
T6 setup-agent.sh, example.env, docs
T7 full test run, Playwright end-to-end, final review
```
T2 ∥ T3 and T4 ∥ T5 touch disjoint files and may run in parallel.

## T1 — Shared renderer (no behavior change)

- Create `backend/app/render_core.py`: pure module (stdlib + markdown/bleach/bs4 only, no
  relative imports) containing `MARKER_RE`, `BARE_PATH_RE`, `IMAGE_EXTENSIONS`,
  `is_image_path`, `path_key`, `ImageContext`, `render_markdown` and helpers — moved from
  `markdown_filter.py` / `images.py`.
- `markdown_filter.py` re-exports `ImageContext`, `render_markdown`; `images.py` imports
  the regexes/`path_key`/`is_image_path` from `render_core` (keep the names importable from
  `images` for existing callers/tests).
- Copy to `agent/agent/render_core.py` byte-identically; add
  `agent/tests/test_render_core_sync.py` asserting equality with
  `../backend/app/render_core.py`.
- `agent/requirements.in`: add `markdown>=3.7`, `pygments>=2.18`, `bleach>=6.0`,
  `beautifulsoup4>=4.12`, `cryptography>=43`, `argon2-cffi>=23.1`. Run `./relock.sh`
  (agent lockfiles only must change; backend lockfiles may be re-resolved — revert backend
  lockfile changes if unrelated). Install into `agent/.venv`.
- Verify: all backend and agent tests green.

## T2 — Agent crypto (agent/agent/e2e.py, agent/agent/e2e_setup.py)

- `e2e.py`: `DEFAULT_KDF`, `derive_master(passphrase, salt_bytes, kdf) -> bytes`,
  `Keys` (enc AESGCM + `check` hex) from master, `encrypt_text/decrypt_text(keys, str, aad)`,
  `encrypt_bytes/decrypt_bytes` (binary magic format), `is_ciphertext`, AAD helper
  functions (one per row of the spec's AAD table), `new_salt()`.
- Test vectors: `agent/tests/fixtures/e2e_vectors.json` generated by a script
  `agent/scripts/gen_e2e_vectors.py` (fixed nonces through an internal `_nonce` parameter);
  `agent/tests/test_e2e.py` checks vectors, round-trips, AAD mismatch failure, tamper
  failure, format.
- `e2e_setup.py` per spec (handshake, PUT params, `--rotate`, existing key reuse), tests
  with `httpx.MockTransport` and monkeypatched `getpass`.

## T3 — Backend E2E mode

- `settings.E2E_ENCRYPTION = _bool_env("E2E_ENCRYPTION", False)`; `docker-compose.yml` +
  deploy scripts pass it through.
- `schema.sql`: `e2e_state` table; jobs CHECK gains `search` (migration generalised from
  `_migrate_jobs_allow_fetch_image`).
- `backend/app/e2e.py`: `is_ciphertext`, `reconcile_mode`, `wipe_content` (spec steps 1–6),
  `get_state`, `set_params` (validation), `binding()`.
- `on_startup`: `reconcile_mode` after `init_db`.
- `db.py`: FTS writes skipped when `settings.E2E_ENCRYPTION`; `get_sessions(ids=...)`; title
  sort fallback in E2E.
- Routes per spec: `/agent/handshake`, `/agent/e2e-params`, `/search`, ingest validation
  (both directions), prompt validation, fetch-image check skip, image store/serve in E2E,
  `ids` filter, `q` ignored in E2E.
- Templates: global `e2e_enabled`; in E2E mode list/detail/jobs render `data-e2e`
  attributes instead of content; `e2e-config` JSON + conditional script tags in
  `base.html` (authenticated pages only); search input without `name`; title-sort option
  hidden; detail page embeds available image keys JSON. Plaintext templates output
  unchanged.
- Tests: new `backend/tests/test_e2e.py` (mode reconcile, wipe + canary binary scan incl.
  WAL and image dir, switch both directions, handshake/params validation, ingest
  validation both modes, search job, ids filter, image E2E store/serve, templates emit no
  plaintext). Existing tests untouched and green.

## T4 — Agent integration

- `config.py`: `e2e: bool`, `e2e_key: bytes | None` (`AI_REMOTE_E2E`, `AI_REMOTE_E2E_KEY`).
- `main.run_cycle`: handshake first (spec table), epoch reset, fail-closed.
- Encryption of outbound data on copies (sync, fetch_full, results, images); prompt
  decryption; new `search` job (`agent/agent/search.py`).
- Tests: fail-closed matrix, epoch reset, canary in all outbound bodies via MockTransport,
  plaintext mode unchanged (existing tests green), search job.

## T5 — Browser

- Vendor `hash-wasm` argon2 UMD and DOMPurify (exact versions ≥ 2 weeks old; SHA-256 in
  `static/vendor/VENDOR.md`).
- `static/e2e-core.js` (UMD) + `static/e2e.js` (unlock overlay, IndexedDB, DOM decrypt,
  forms, search, images, jobs page, logout) + app.js hooks (`window.e2eReady` gating of
  content initializers; image `show` via decrypt in E2E) + i18n strings (de/en) + CSS.
- `backend/tests/js/e2e_core.test.mjs` (`node --test`) verifying the Python vectors;
  `backend/tests/test_e2e_js.py` runs it (skips if `node` missing).

## T6 — Ops & docs

- `setup-agent.sh` per spec; `example.env` documents `E2E_ENCRYPTION`; README, SECURITY.md
  (threat model, what is/isn't protected, backup deletion), agent/README.md.

## T7 — Verification

- `cd backend && .venv/bin/pytest`, `cd agent && .venv/bin/pytest`, `node --test`.
- Playwright run: local backend with `E2E_ENCRYPTION=true`, real agent code seeding
  fixture sessions (with images) against it, unlock → list → detail → image → search →
  command → jobs page → logout; then binary-grep `app.db*` and image dir for the canary.
- Final whole-branch review by a fresh reviewer; fix findings; re-run everything.

## Risks / rollback

- Rollback: `E2E_ENCRYPTION=false` → server wipes and the agent resyncs plaintext.
- Risk: renderer drift between backend and agent copy → sync test.
- Risk: Argon2 parameters too slow on old phones → parameters stored per deployment and
  changeable via `--rotate`.
